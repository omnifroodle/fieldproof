ONCE IT SYNCS, IT IS JUST DATA IN CAPELLA

SELECT META().id AS id, district, status, category,

       location.lat AS lat, location.lon AS lon

FROM `demos`.evidence.reports

WHERE type = "report"

  AND attachedTo IS MISSING

  AND ($district IS NULL OR district = $district)

ORDER BY createdAt DESC

Two paths, each doing its job

Questions go to the cluster as SQL++, with RequestPlus.

Bytes and status writes go through App Services, so a change reaches the crew.

No polling: a longpoll on the changes feed puts a new report on this map in about 3 seconds.

The map updates itself: the server holds a longpoll on the App Services changes feed and pushes an event to each open dashboard. Measured at about 3 seconds from filing a report on the phone. One SQL++ statement draws the map; the supervisor's filters are parameters, not application code. Express, Leaflet, no build step, about 530 lines of JavaScript. The point is not the dashboard — it is that data a phone wrote in a canyon is ordinary Capella data the moment it lands.
